# Session Audit: 2026-10-10 — Multi-Store Telegram Mini App E-Commerce & Per-Store ABA PayWay Integration

## Overview
This session resolved the architecture, documentation, and implementation for the **Multi-Store Telegram Mini App E-commerce** ecosystem, enabling independent brands (e.g. 10 distinct coffee shops with 10 different owners) to operate autonomously on the unified platform with dedicated Telegram Mini App channels, per-store ABA PayWay merchant isolation, and an interactive Admin Storefront Hub.

## 1. Key Architectural Implementations

### 1.1 Multi-Tenant Data Isolation (The 10 Coffee Shops Model)
- **Bounded Context**: Each coffee shop is an independent `Organization` (`organizations` table) with its own `id`, `name`, `slug`, `currency`, and `taxRatePct`.
- **RBAC**: Store owners have `User` accounts with role `ORG_ADMIN` linked strictly to their `organization_id`. Store owners can only view and mutate data belonging to their organization.
- **Store Provisioning API**:
  - `POST /api/v1/organizations`: Provisions a new store with slug, creates a default `BRANCH` location, and optionally provisions the initial store owner admin account with hashed password.
  - `GET /api/v1/organizations`: Lists all provisioned stores (for `SUPER_ADMIN`) or returns current tenant store (for `ORG_ADMIN`).

### 1.2 Multi-Store Telegram Mini App Channels Hub
- **Channel Discovery API**:
  - `GET /api/v1/organizations/current/channels` and `GET /api/v1/organizations/{id}/channels`: Returns live channel metadata including:
    - `telegramMiniAppUrl`: `https://admin.camtech.cam/mini?org={organizationId}`
    - `storefrontUrl`: `https://admin.camtech.cam/shop?org={organizationId}`
    - `publicCatalogEndpoint`: `/api/v1/public/products?organizationId={organizationId}`
    - `checkoutEndpoint`: `/api/v1/sales/checkout`
    - `paywayConfigured` & `paywayMerchantId`: Live verification of ABA PayWay readiness.
- **Admin Management Page**:
  - Created [apps/web/app/storefront/page.tsx](file:///d:/Project/MyStore/apps/web/app/storefront/page.tsx) at route `/storefront` under **Commerce** -> **Storefront & Mini App**.
  - Includes a Store Selector, "Provision New Store" modal, live Telegram Mini App QR Code generator, BotFather command cheatsheet (`/setmenubutton`), ABA PayWay status card, and Developer Endpoints Directory.

### 1.3 Per-Store ABA PayWay Dynamic Merchant Binding
- **Problem**: When 10 coffee shops share the platform, payments must route to each shop's individual ABA bank account, not a pooled platform account.
- **Solution**:
  - In [checkout_controller.py](file:///d:/Project/MyStore/services/backend-py/app/modules/sales/controllers/checkout_controller.py), the checkout engine queries `payway_configs` where `organization_id == target_org`.
  - Dynamically loads that store's ABA `merchant_id` and RSA private key to compute the HMAC-SHA512 transaction signature.
  - Generates store-specific KHQR codes and ABA mobile app deep links that settle funds directly into that coffee shop's merchant account.

### 1.4 Public Catalog Multi-Tenant Scoping
- Updated [catalog/api.py](file:///d:/Project/MyStore/services/backend-py/app/modules/catalog/api.py):
  - `GET /api/v1/public/products` accepts `organizationId` or `slug` query parameters, ensuring Mini Apps and Web Stores display only products belonging to that specific store.
  - `GET /api/v1/public/categories/tree` accepts `organizationId` or `slug` to display store-specific menu categories.

## 6. Dynamic Multi-Tenant Bakong KHQR Integration (Zero Hardcoded Data)

### 6.1 Requirements & Architectural Invariants
- **100% Dynamic Per-Store Resolution**: No Bakong account IDs, merchant display names, or bank tokens may be hardcoded.
- **Tenant Isolation**: Each store/organization configures its own National Bank of Cambodia (NBC) Bakong Account ID (e.g. `store@aclb`, `merchant@wing`, or phone number), store display name, city, and currency (`USD`/`KHR`).
- **Dynamic Checkout Routing**: When customers checkout via Web Storefront (`/shop`), Cashier POS, or Telegram Mini App (`/mini`), the checkout engine dynamically resolves the target store's settings and mints the EMVCo KHQR code directly tied to that specific merchant.

### 6.3 Strict Multi-Tiered Validation & NBC Live Verification
- **User Finding**: Noticed that the system previously allowed saving unverified or arbitrary data without validating whether the Bakong account is real or active on the National Bank of Cambodia network.
- **Resolution**:
  1. **Schema-Level Validation**: Added strict Pydantic v2 `field_validator` on `UpdateBakongConfigInput`, `CreateOrganizationInput`, and `VerifyBakongAccountInput` enforcing RFC-compliant handles (`username@bank` or Cambodian phone numbers `855xxxxxxxxx`), rejecting spaces, malformed characters, and invalid currencies.
  2. **Live NBC Verification Gate**: In `PUT /api/v1/organizations/current/bakong`, any attempt to configure an account triggers a live lookup on `https://api-bakong.nbc.gov.kh/v1/check_bakong_account`. If NBC returns an error code (such as `11: Account not found` or `12: Account ID is invalid`), the backend immediately aborts and returns `HTTP 400 Bad Request` with the exact NBC error message, preventing broken or corrupted configuration.
  3. **Interactive Verification in Admin UI**: Added a dedicated **"Verify on NBC Network"** button in [bakong-settings.tsx](file:///d:/Project/MyStore/apps/web/app/settings/bakong-settings.tsx). Store owners receive immediate real-time feedback with the verified owner name returned from NBC (`accountName`) before saving.
