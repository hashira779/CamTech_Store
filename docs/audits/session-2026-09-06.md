Bound `User.user_roles` relationship in `identity/models.py`. Implemented dual-write in `identity/api.py` and dual-read via `selectinload` in `dependencies.py`. | Fully relational RBAC schema with foreign key integrity, maintaining 100% backward compatibility with `user.roles` string getter. |
| **Distributed Sliding-Window Rate Limiting** | FINDING-MED-01 / Principle 14, 43 | Upgraded `RateLimiter` in `app/core/rate_limiter.py` to use Redis atomic ZSET operations (`ZREMRANGEBYSCORE`, `ZCARD`, `ZADD`, `EXPIRE`) with graceful in-memory fallback. | Prevents brute-force bypass across multi-worker and multi-container deployments; verified via `test_api_security.py`. |
| **Automations Router Decomposition** | FINDING-LOW-01 / Principle 10, 17 | Decomposed 1,007-line `automations/api.py` into 4 cohesive controllers: `telegram_controller.py`, `developer_apps_controller.py`, `webhooks_controller.py`, and `flows_controller.py`. | Root router reduced to 22 lines of clean composition. Zero contract or route drift. |
| **Sales Router Decomposition** | FINDING-LOW-01 / Principle 10, 17 | Decomposed 867-line `sales/api.py` into 3 cohesive controllers: `pos_controller.py`, `checkout_controller.py`, `orders_controller.py`, and `helpers.py`. | Root router reduced to 23 lines. Zero route drift. Verified against `test_order_alerts_pipeline.py`. |
| **Distributed Observability & Telemetry** | Principle 47, 48 (Observability & Logging) | Implemented `app/core/telemetry.py` with `StructuredJsonFormatter`, `TelemetryMiddleware`, context variables (`current_trace_id`, `current_span_id`, `current_request_id`). Integrated into `main.py` and `common.py`. | Emits JSON logs correlated with `requestId` and `traceId`. Configured `otel-collector` and `jaeger` in Docker Compose. Verified via `test_telemetry.py`. |
| **Database Connection Resilience (PgBouncer)** | Principle 68 (High Availability) | Configured `pgbouncer` container (`edoburu/pgbouncer:latest`) in `docker-compose.yml` and `docker-compose.prod.yml` in transaction pooling mode (port 6432, 2,000 max clients). | Protects PostgreSQL from connection pool exhaustion under high concurrent load. |
| **Read-Replica Query Routing** | Principle 14, 50 (Scalability & Performance) | Implemented `get_read_db` in `app/core/database.py` with `read_engine` pointing to `REPLICA_DATABASE_URL`. Routed `/reports/summary`, `/reports/dashboard`, and `/reports/export` to `get_read_db`. Configured `postgres-replica` on port 5434 in Docker Compose. | Offloads heavy reporting aggregation from the transactional primary database. |
| **Kubernetes Autoscaling (HPA)** | Principle 69 (Horizontal Scaling) | Created production Kubernetes manifests in `infra/k8s/`: `namespace.yaml`, `gateway-hpa.yaml`, and `microservices-hpa.yaml` with HPAs scaling from 2 to 12 replicas on 70% CPU / 80% Memory. | Cloud-native readiness for auto-scaling under peak burst traffic. |
| **Playwright Automated E2E Regression Suite** | Principle 53, 55 (QA & CI/CD) | Created `apps/web/playwright.config.ts`, `apps/web/e2e/auth-flow.spec.ts`, and `apps/web/e2e/catalog-checkout.spec.ts`. Added `"test:e2e"` script and GitHub Actions CI job `e2e-playwright`. | Automated browser-level regression testing across desktop and mobile viewports. |
| **Phase 5 Saga & Database Blueprint** | Principle 73, 75 (Microservices & Domain Isolation) | Authored `docs/architecture/microservices-per-service-database.md` outlining standalone schema extraction for Delivery and HR domains, outbox message contracts, and saga compensation flows. | Clear blueprint for future team-level deployment isolation as business demands scale. |
