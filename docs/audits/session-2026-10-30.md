# Session 2026-10-30 — Platform foundation: edge, routing, structure

Scope: standardize the shared backend layers, repair gateway behaviour, tidy the repo root, and start the UI token
burn-down. Verified with the full test suite, a live gateway + 9 services run on the local DB, and a browser pass.

## Defects fixed (each reproduced by a failing test first)

| Defect | Effect | Fix |
|---|---|---|
| Gateway replayed a write in-process after any upstream failure | A timed-out `POST /sales` that had already committed could run twice | Writes fall back only when the request never reached the service; otherwise `504 UPSTREAM_TIMEOUT` / `502 UPSTREAM_FAILED` |
| Fallback received an already-consumed request body | `POST` hung during failover | Body is replayed to the fallback app |
| Service envelope ran inside GZip | Responses of 1 KB or more lost `{success, data, requestId}` when the client accepted gzip | GZip is outermost (`add_gzip`) |
| Prefix match had no path boundary | `/api/v1/authorize` routed to the auth service | `resolve_service` matches a whole segment |
| Headers copied through a `dict` | All but one `Set-Cookie` lost | Raw headers preserved in the gateway and envelope |
| `/health` reported hardcoded "healthy" and omitted two services | Monitors could not see an outage | Probes each service; `status` is `healthy` or `degraded`, HTTP stays 200 |
| 17 `/api/v1/observability/*` routes mounted on no service | 404 behind the gateway (no frontend caller today) | Mounted on the infra service |
| Rate-limit exception raised outside `ExceptionMiddleware` | 429 surfaced as 500 on the monolith | Returned as an enveloped `RATE_LIMITED` 429 |
| Services flattened structured error details | Authorization details arrived as a Python repr | Same handler as the monolith |
| `/metrics` and service `/health` reported invented values | Fake 25,000 req/s, fake "DB Connected" | Removed |

## New structure

- `app/core/http_edge.py` — one definition of envelope, errors, tracing and security headers. `EdgePolicy` declares what
  legitimately differs between the monolith and a service behind the gateway.
- `app/microservices/registry.py` — one definition of services, ports and owned URL prefixes.
  `test_every_monolith_route_is_served_by_the_service_the_gateway_picks` fails on any misroute.
- `apps/web/src/experiences.ts` — table-driven experience selection, with whole-segment path matching.
- `scripts/check-ui-tokens.mjs` (`pnpm ui:check`, in CI and `audit:check`) — hex literal ratchet per file.
- `audit:check` now also runs `py:test`, which AGENTS.md already claimed it did.

## Known gaps, not changed

- **Production telemetry:** capture, ingestion and detection start only in the monolith lifespan, which never runs behind
  the gateway, so `obs_*` tables receive no production traffic. Enabling it writes to the production DB.
- **Rate limiting and scanner guard** run only on the monolith edge. Behind the gateway, nginx is the only rate limit.
  Enable with `EdgePolicy(rate_limit=True)` in `create_microservice`.
- **Coupled services:** all services share one database and import each other's models; see
  `microservices-per-service-database.md`.
- **Large page files** (`app/mini/page.tsx` 78 KB, `app/driver/page.tsx` 61 KB) and 661 hex literals remain. Burn down when
  touching a screen, per the UI guidelines.
- **Legacy trees:** `services/backend` (NestJS) and `app/routers` + `app/services` alongside `app/modules`.

## Second pass: security, look, speed

**Security.** `app/core/access_policy.py` adds role checks; before it a cashier could post journal entries, create
employees, change products and adjust stock, and read employees and accounts. Removed a committed Telegram bot token and
fallback `JWT_SECRET`/`POSTGRES_PASSWORD` from `docker-compose.prod.yml` (deploy now fails if the latter two are unset).
Escaped the invoice's stored values (stored XSS with same-origin token access). Demo logins render only in dev builds.
Removed CSP `unsafe-eval`.

**Look.** New token palette passing WCAG AA, and a codemod moved status colors to tokens across `apps/web`; internal
screens also moved neutrals and brand hex. Consumer surfaces kept their branding and only changed status colors. Removed
invented figures from the login page and infra overview, and the order count shown as a percentage on the sales page.

**Speed.** First-load assets went from about 1,000 KB to about 500 KB by no longer forcing recharts and icons into the
entry; command palette and copilot load on demand.

**Not done.** Tokens stay in `localStorage` (HttpOnly cookies would need an auth redesign). `apps/store`, `apps/cashier`,
`apps/delivery`, `apps/hr`, `apps/ceo` and `apps/mini` keep their own themes. `script-src` still has `unsafe-inline`.
Navigation does not yet hide areas a role can no longer access, so those users see a 403 message instead.

## Folder structure

Moved `app/routers` into `app/modules/<domain>/api.py`, removed unused `app/schemas/dto.py`, moved stray backend
scripts into `services/backend-py/scripts/`, and grouped `scripts/` into `deploy/`, `ops/` and `dev/`. Conventions are in
`docs/architecture/folder-structure.md`. `deploy_production.sh`, `camtech.py` and `backup_db.py` stay put because CI, the
server's auto-deploy service and the guides call those paths.

Deleted `scripts/remove_hardcoded_passwords.py`: it had a syntax error and held a server password in plain text. That
password remains in git history and must be rotated.

## Load balancing

Real state and remaining steps are in `docs/architecture/load-balancing.md`. Ingress now survives a missing frontend and
reuses gateway connections; database pools were cut so the fleet fits within Postgres connections; containers have
healthchecks; data ports bind to loopback. The nginx config has not been run locally; CI validates it before deploy.
